# Ревью повторной игры и стыковки этажей

21 октября 2026.

## Изменения

- Удалены подсказка «Нажми, чтобы сбросить этаж», её белая плашка и пояснение про баланс. Удалён неиспользуемый компонент и его CSS.
- У стартового текста удалены тень и тёмная обводка. Оставлена белая заливка; браузерная проверка сверяет фактические CSS-значения.
- После открытки группа сцены восстанавливает масштаб, положение, видимость и мировые матрицы в layout effect. Это закрывает зависимость от порядка кадра и passive effects Rapier: новые тела не должны запоминать уменьшенный трансформ финала. Контрольный запуск без исправления не воспроизвёл исчезновение стабильно, поэтому это устранение найденного риска порядка инициализации, а не доказательство единственной причины всех исчезновений.
- Число инстансов этажей задаётся из фактического списка буферов вместо постоянного JSX `count={0}` и отдельной императивной записи. Матрицы башни создаются один раз и переиспользуются всеми её частями; венки получают отфильтрованный список. Сброс и новый раунд обновляют и число этажей, и их координаты в одном React commit.
- Убрано намеренное дрожание камеры после обычной успешной стыковки. Оно могло восприниматься как рывок. Дрожание при неудаче сохранено.

## Проверки

- 101 тест в 20 файлах; TypeScript без ошибок.
- `scripts/check-game-runtime.mjs`: три полных физических прохода по 15 этажей с чередующимися смещениями ±0.3 м. В каждом проходе — ожидание полного уменьшения и скрытия сцены за открыткой, затем повторный запуск.
- На каждой из 45 посадок проверяются фактические количества инстансов фасадов и снега, высоты всех этажей, масштаб и видимость сцены. Во время падения проверяется допустимый диапазон координат движущейся модели.
- Три физических промаха, автоматический новый раунд; пять однонаправленных смещений, физическое обрушение, новый раунд и точная посадка.
- CPU-профиль восьми посадок: повторяющегося тяжёлого расчёта в игровой физике не найдено. Основная работа — React в режиме разработки и Three/WebGL. Первичный замер одновременно со сборкой содержал длинные задачи; для финального замера сборка не выполнялась параллельно.
- Итоговый браузерный прогон: 45 этажей, 3 промаха, 1 обрушение, 0 ошибок приложения и 0 выходов движущегося этажа из допустимой траектории. Медиана времени кадра 16.7 мс, p95 16.8 мс. В окне ±100 мс от посадок: 551 кадр, медиана 16.7 мс, p95 16.8 мс, максимум 83.2 мс. Отдельные длинные задачи остаются, поэтому этот результат не означает полного отсутствия задержек.

Браузерный тест использует установленный отдельно Playwright и Chrome, не добавляет их в зависимости игры. Запуск при работающем dev server:

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright node scripts/check-game-runtime.mjs
```

Если Playwright доступен обычному Node resolution, переменная не нужна. `GAME_URL` меняет адрес dev server, `GAME_REPORT` — путь JSON-отчёта (по умолчанию `/tmp/ida-runtime-report.json`). Скрипт использует диагностические импорты Vite; для production URL он не предназначен.

## Границы проверки

Проверено в Chrome на компьютере с viewport 390 × 844 и полными high-ассетами. Реальные iOS/Android и Telegram WebView не проверялись. Плавность на телефоне требует аппаратного замера; отсутствие всех возможных лагов не заявляется. Игровые пороги, таймеры и разрешение рендера не менялись.
