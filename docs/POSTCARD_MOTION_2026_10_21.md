# Наклон открытки от положения телефона

Мобильная открытка использует браузерный `DeviceOrientationEvent`. Датчики включаются только для устройства с coarse pointer, в secure context и без `prefers-reduced-motion`. Новых зависимостей нет.

Первое корректное показание задаёт нейтральное положение. Изменения beta/gamma управляют теми же координатами, которые уже используются для наклона и голографического блика. Поворот телефона на 30° даёт максимум 9° наклона открытки; существующее сглаживание не зависит от частоты экрана. Некорректные показания и мелкий шум игнорируются. Поворот экрана учитывается при выборе осей и сбрасывает калибровку.

Если браузер предоставляет `requestPermission()`, разрешение запрашивается после касания открытки, кликом или Enter. До этого под открыткой показана строка «Коснись, чтобы включить наклон». Она не закрывает изображение и исчезает после запроса. Выданное разрешение переиспользуется при повторной игре в той же странице. На браузерах без отдельного permission API слушатель включается автоматически. Отказ или ошибка сохраняют управление пальцем и клавиатурой.

Требование пользовательского жеста и значения углов сверены со [спецификацией W3C](https://www.w3.org/TR/orientation-event/).

Во время касания приоритет у пальца; после отпускания возвращается наклон от телефона. Пауза и скрытая вкладка не принимают показания и не рисуют новые кадры. При возвращении положение калибруется заново. При уходе с открытки слушатель датчиков удаляется вместе с остальными обработчиками. Поздний ответ на разрешение после unmount не подключает датчики и не обновляет React.

Проверено:

- 114 тестов, включая 23 проверки голографического эффекта: калибровка, пределы, landscape, переход beta через ±180°, некорректные данные, приоритет касания, пауза/фон, grant/deny/reject, Enter/click, повтор и позднее разрешение после unmount.
- TypeScript и production build с базовым путём GitHub Pages.
- Chrome с мобильным вводом, DPR 3, 390 × 844 и 320 × 568: изменения ориентации через CDP, автоматический путь без отдельного permission API, настоящее разрешение Chrome и имитация permission API iOS. Проверка user activation при касании, исчезновения подсказки и отсутствия пересечения с кнопками. Аппаратный iPhone и Telegram WebView не использовались.

Игра, отрисовка этажей и игровые таймеры не менялись.
