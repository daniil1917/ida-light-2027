# Построй 2027 · Ида Лайт

Браузерная 3D-игра для новогоднего Telegram Mini App. **Версия 0.24.0:** полный цикл из 15 этажей, зимняя архитектурная сцена, кинофинал, две голографические открытки PNG и повторная игра.

Мобильное качество и аудит 0.24.0: [отчёт](docs/RELEASE_024_MOBILE_REVIEW.md).

Исправление 0.23.1: [смена открытки после каждой победы](docs/RELEASE_0231_FIX.md). Открытка выбирается заново без повтора предыдущего варианта. При двух открытках они чередуются; предзагрузка и финальный экран используют один выбор на победу.

Правки 0.23.0: [отчёт по переливу, двум открыткам и финалу](docs/RELEASE_023_REVIEW.md). Неподвижная область наведения и обновление эффекта во время наведения, отступы 32 px на десктопе, скорость ещё примерно на 4% выше, больше конфетти. На финальном экране — случайно назначенная открытка, синяя кнопка сохранения и белая кнопка повторной игры.

Полное ТЗ: [PRODUCT_BRIEF.md](docs/PRODUCT_BRIEF.md). Этапы и критерии: [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md). Архитектура: [ARCHITECTURE.md](docs/ARCHITECTURE.md). Аудит источников: [THIRD_PARTY.md](THIRD_PARTY.md).

## Запуск

Требуется Node.js 22.12+ (рекомендуется 24 LTS) и npm.

```bash
npm install
npm run dev
```

Открыть http://127.0.0.1:5173. На мобильном устройстве потребуется доступный HTTPS origin; dev server по умолчанию привязан к loopback.

```bash
npm run test
npm run typecheck
npm run build
npm run preview
```

`npm run preview`: http://127.0.0.1:4183. Новая сборка — `dist-next/`. Прежний `dist/` (0.15.0) сохранён: `npm run preview:legacy`, http://127.0.0.1:4173.

Подключение новой сцены и проверки: [WINTER_INTEGRATION.md](docs/WINTER_INTEGRATION.md).

Правки отображения и цвета: [WINTER_UI_REVIEW.md](docs/WINTER_UI_REVIEW.md). Высота сброса — 3,9 м; игровой счётчик — одна строка 44 px, без белых градиентов поверх сцены.

Финальная доводка 0.18.0: [FINAL_POLISH_REVIEW.md](docs/FINAL_POLISH_REVIEW.md). Доводка 0.19.0: [RELEASE_019_REVIEW.md](docs/RELEASE_019_REVIEW.md). Единая палитра, плавный переход и один звук посадки 0.20.0: [RELEASE_020_REVIEW.md](docs/RELEASE_020_REVIEW.md). Голографическая открытка и новый финал 0.21.0: [RELEASE_021_REVIEW.md](docs/RELEASE_021_REVIEW.md). Максимальное качество: http://127.0.0.1:4183/?v=0.24.0 — исходные high-атласы, DPR 3 с бюджетом 5 млн пикселей, без автоматического снижения. По обычному адресу на всех устройствах используются эти же high-атласы и DPR 3 (до 5 млн пикселей), без скрытого понижения качества. `?quality=auto` включает адаптивное разрешение; `?quality=mobile` явно выбирает облегчённые текстуры.

## Готовый игровой цикл

- React + TypeScript + Vite; R3F/Three.js, Drei, React Three Rapier, Zustand.
- Новая согласованная сцена Blender: пять GLB с запечённым освещением, мебелью, мягким снегом и праздничным декором. Телескопический кран растёт из неподвижной опоры, подача чередуется. Размер этажа и коллайдера 3.72 × 1.35 × 3.22 м.
- Perfect при overlap ≥94%, success ≥62%, иначе fail. Пороги вынесены в config.
- Все посадки сохраняют фактическую координату контакта, включая Perfect. Падение вертикальное без помощи.
- В раунде три жизни. Первые два промаха сохраняют башню и через 750 мс дают повтор; третий показывает сообщение и через 2.5 секунды начинает новый раунд с нуля.
- При выходе центра массы верхней части за контактную опору башня теряет устойчивость. Верхняя часть опрокидывается под гравитацией, затем начинается новый раунд через 3.5 секунды или позже для высокой башни, чтобы она успела упасть. Обычные промахи по-прежнему расходуют три жизни.
- В обычной игре одна динамическая секция и один fixed collider верхней опоры; поставленные этажи — meshes. Для обрушения создаётся отдельный физический мир: одно compound body, временный шарнир на краю опоры и ground collider. После наклона 30° шарнир отпускает дом с накопленной скоростью; удар поглощается без стартового импульса вверх.
- Tutorial после первого нажатия исчезает. Управление: касание/мышь, Space или Enter на игровой области.
- Шесть диапазонов сложности: скорость 1.175 → 1.737 и амплитуда 2.17 → 2.666. Последний этаж сохраняет темп 14-го. При пересечении центра окно успешного сброса сужается примерно с 1207 до 643 мс.
- Плавная ортографическая камера следует за верхней опорой; после 15 этажей показывает всю башню. Полные атласы и DPR 3 (до 5 млн пикселей) используются по умолчанию; адаптация по времени кадров доступна только через ?quality=auto.
- Уложенные этажи используют постоянные InstancedMesh, движущийся этаж — обычные shared meshes. Физические тела не растут с башней.
- Запечённые тёплые комнаты и мягкий снег сохраняют утверждённый свет. Кран и лампочки используют PBR/AgX, запечённые атласы проходят тональную обработку только один раз. Подвижная тень падающего этажа и сжатие снега под фактическим смещением следующего модуля. Ореолы лампочек — один инстанс, без сотен источников света.
- Снег покрывает весь игровой экран и движется на GPU, без обновления координат снежинок с CPU каждый кадр. Пауза останавливает снег; reduced motion оставляет статичный вариант. Логотип белый, загрузка — на фирменном синем фоне.
- Howler: один короткий CC0 звук успешной установки без фонового звука и сигнала полёта, запуск после user gesture, постоянно доступный sound toggle, сохранение предпочтения и pause в фоне.
- Haptics: light/soft на посадке и success notification в конце, только внутри поддерживаемого Telegram.
- Telegram shell: user, viewport, safe areas, theme variables, back button и lifecycle через tma.js SDK. В обычном браузере работает без Telegram.
- Loading, WebGL2 fallback, обработка ошибок загрузки/контекста, pause в фоне, reduced UI motion.
- 15 этажей → отъезд камеры → 2027 на снежной крыше → снег/confetti → персональное пожелание → replay. Готовый дом отдаляется за 900 мс, затем главный экран занимает голографическая открытка. Небо и снег остаются непрерывными. Утверждены две открытки; следующие добавляются в каталог GREETINGS с id, title, text, artwork и alt. На каждой победе случайно выбирается вариант, кроме предыдущего; при двух открытках они чередуются. Предыдущий результат сохраняется локально, но не закрепляет открытку за пользователем. Это распределение с возможными совпадениями, а не глобальная выдача уникальных экземпляров.

## Настройки разработки

В `npm run dev` с параметром `?debug=1` внизу справа раскрываются **«Настройки разработки»**: фактический диапазон сложности, draw calls, geometries/textures, число физических тел, gravity, overlap thresholds, camera zoom, Rapier collider debug. Speed/amplitude sliders действуют после включения «Ручная скорость и амплитуда». Кнопки «Точно», «Со смещением», «Промах» выставляют стартовую позицию сброса и запускают настоящий физический drop. Они не добавляют этаж напрямую. Также доступны phase финала, pause, статичная cinematic QA ветка и просмотр всех вариантов пожеланий. В production debug component отсутствует.

Важные файлы:

- `src/game/gameConfig.ts`: размеры, gravity, пороги, задержки, target=15, lives=3 и естественное падение.
- `src/game/difficulty.ts`: скорость, амплитуда и помощь по диапазонам.
- `src/scene/WinterAssets.tsx`: shared geometry/materials и выбор high/mobile; `public/winter/`: готовые модели.
- `src/app/visualConfig.ts`: параметры камеры.
- `src/scene/IdaMaterials.tsx`: общий набор PBR-материалов.
- `src/assets/assetPaths.ts`: локальные URL и паттерн модулей.
- `src/app/performanceConfig.ts`: high/medium/low, DPR и размер теней. `qualityGovernor.ts`: снижение после двух медленных трёхсекундных окон (<45 FPS), восстановление после 30 секунд ≥58 FPS; фон/одиночные stalls не учитываются, неудачное повышение откладывает новую пробу на 120 секунд.
- `src/game/greetings.ts`: каталог утверждённых открыток и выбор без повтора предыдущей победы; две карточки: олень и бумажная ёлка.
- `src/ui/ida/GreetingCard.tsx`: финал с открыткой и двумя Fluid-кнопками на всю ширину. `HolographicCard.tsx` / `holographicEffect.ts`: наклон и шейдер фольги из HTML, с неподвижной плоскостью ввода, изолированным слоем canvas и обновлением перелива во время наведения в 0.23.0. `greetingImage.ts`: сохранение исходного PNG 1052×1494 без перерисовки.
- `src/app/layout.ts`: отступы безопасной области 3D соответствуют сетке CSS.
- `src/app/brand.json`, `src/styles/brand.css`, `tokens.css`: фирменные цвета, Euclid Circular A и safe-area CSS.
- `src/game/store.ts`: состояние игры, события, attempt/session guards.
- `src/physics/FloorPhysics.tsx`: падение, контакты и промах без контакта.

В интерфейсе используются только синий сайта Ида Лайт `#245BF3`, чёрный, белый и серые. Пользовательский Euclid Circular A подключён локально для интерфейса, PNG и 3D-цифр.

## Telegram

1. Собрать приложение и разместить `dist/` на HTTPS hosting.
2. В BotFather настроить Mini App / menu button с HTTPS URL.
3. Для share текста и ссылки указать `VITE_TELEGRAM_APP_URL` в `.env` по образцу `.env.example`.
4. Проверить iOS Telegram, Android Telegram и Desktop: safe areas, resizing, back и возвращение из фона.

Bot token в frontend не нужен и не должен попадать в `VITE_*`. `initData` здесь используется только для персонализации; серверная авторизация и analytics не добавлены. Самого бота и публикации текущий этап не создаёт. Browser-проверка не заменяет тест на реальных Telegram clients.

Документация: [официальная Telegram Mini Apps](https://core.telegram.org/bots/webapps), [tma.js SDK](https://docs.telegram-mini-apps.com/packages/tma-js-sdk).

## Ассеты и оптимизация

Локальные GLB: база, A/B/C, special, крыша, кран, зимняя площадь, набор фасадных гирлянд/венков и запечённый квартал. Meshopt, weld/dedup/prune; UV сохранены для материалов. Актуальные размеры, bounds, SHA-256 и glTF validation: [assets-report.json](docs/research/assets-report.json). В каждом этаже есть Structure / Glass / WindowLights. Размер 3 × 0.82 × 2.65 совпадает с collider; бетонная плита и верх снега больше не лежат в одной плоскости.

Фасад собран из остеклённого сегмента Kenney `building-skyscraper-a`; основание и крыша используют сохранённую массу генератора glb-buildings-skill (MIT). Площадь и декор — Kenney City Commercial / Holiday Kit (CC0), украшения сохраняют цвета пакета. Бетонные карты Poly Haven (CC0) — нейтральные 512px WebP. Квартал использует запечённый свет в одном материале; башня и кран — динамический свет/тени. Динамические тени сохраняются во всех режимах: 2048 / 1024 / 512. 2027 — Text3D из Euclid Circular A. При reduced motion снежинки неподвижны.

До старта готовятся все типы этажей, крыша, шрифт, квартал, шейдеры и код пожелания/конфетти. Все runtime URL локальные, CDN моделей/шрифтов отсутствуют.

Воспроизведение ассетов:

```bash
# Модели используют сохранённую массу генератора из assets/buildings/.
npm run assets:build
npm run assets:optimize
blender --background --python scripts/bake-quarter.py
python3 scripts/pack-lightmap.py
npm run assets:pack-quarter
npm run assets:inspect
npm run assets:font
# Python 3 + Pillow/NumPy для lightmap; FontTools + Brotli для WOFF2.
python3 scripts/prepare-textures.py
python3 scripts/prepare-brand-fonts.py
```

Запекание квартала описано в [ASSET_PIPELINE.md](docs/ASSET_PIPELINE.md). Редактируемый свет и материалы: `assets/baked/quarter-lighting.blend`. Для повторного запекания нужен Blender; для игры он не нужен.

`scripts/generate-audio.py` воспроизводит собственные короткие CC0 эффекты 48 кГц без фонового трека (Python 3). Готовые файлы включены в public/audio. Источники, точные лицензии выбранных пакетов и изменения перечислены в [THIRD_PARTY.md](THIRD_PARTY.md); distribution notices — public/ASSET_NOTICES.md.

Кинофинал: [CELEBRATION.md](docs/CELEBRATION.md). Код финала готовится при загрузке; composer работает только в high. Pause/replay отменяют поздние cues и освобождают targets/canvas.

Карточка загружается отдельно и подготавливается во время загрузки сцены. В 0.22.0 на финальном экране только рисунок, синяя кнопка «Сохранить открытку» и белая «Построить ещё раз». Видимые подписи и отправка удалены, инструкции для скринридера и клавиатура сохранены. Обе кнопки — Fluid, на всю ширину с общими боковыми отступами: 36px от 480px ширины, 20px на мобильной ширине, 16px до 350px. PNG побайтно совпадает с рисунком из предоставленного HTML. Полоса блика ограничена 20–80% изображения, поэтому не уходит за края в крайних положениях. WebGL сохраняет последний кадр; уведомление об одинаковом размере не очищает буфер. В покое нет постоянного RAF-цикла; пауза замораживает наклон, reduced motion убирает наклон и масштаб. Потеря WebGL оставляет видимым исходный рисунок.

3D сцена и SDK загружаются динамически. В текущей сборке 3D chunk включает Three.js и встроенный Rapier WASM: примерно 3.3 MB minified / 1.13 MB gzip. Vite сообщает о chunk >500 KB; это известный размер пакета Three/Rapier, не ошибка сборки; сцена занимает несколько MB и загружается отдельно от интерфейса. Rapier dependency также выдаёт предупреждение о старой форме внутренней WASM initialization; upstream код не патчился. Измерения FPS на телефонах ещё не проведены.

## Правки рождественской сцены · 0.7.1

Кран закреплён на земле: Foot, секционная instanced-мачта и Boom. Стрела статична по горизонтали и поднимается только при добавлении этажей; мачта сохраняет непрерывность от y=0. В финале камера учитывает высоту крана. Каретка/подвес следуют движущемуся этажу.

Официальный SVG взят из header `.TheLogo` сайта idalite.ru: пути без изменений, белая версия на тёмном фоне. Он используется в шапке, загрузке и PNG. Favicon использует первую букву этого wordmark. Euclid Circular A сохранён.

По новой инструкции пользователя праздничные предметы сохраняют оригинальные atlas-цвета Kenney через линейные vertex colors. Добавлены снеговик, леденец, венок, гирлянда, подарок и шесть сугробов. Snow: 420/240/80 частиц, скорость/размер/непрозрачность усилены; reduced-motion сохраняет неподвижность, доступная пауза останавливает сцену. Фасад — нейтральный камень, стекло — естественный серый оттенок, свет окон менее яркий. UI сохраняет фирменную палитру.

Отчёт по шести UI-навыкам и локальная приёмка: [UI_REVIEW.md](design/revision-0.7.1/UI_REVIEW.md). Проверены 10 пожеланий на 320px, клавиатура/фокус/диалог, семь viewport, low/static и replay. Реальные Telegram-клиенты и FPS на телефоне требуют отдельного теста.

## Статичный кран и границы строительства · 0.7.2

Мачта и её основание стоят позади траектории этажей (z=-2.4). Поперечная ферма соединяет их со стрелой над домом. Центр установленных этажей ограничен ±1.5; допустимые попадания наружу плавно направляются внутрь во время падения, полные промахи не спасаются. Предел амплитуды 2.8 и длина стрелы 9.33 учитывают ширину тележки и концевые упоры. Камера сохраняет центр площадки и учитывает весь размах активного этажа. Единые параметры — src/game/constructionConfig.json. Проверка: [CRANE_VERIFICATION.md](design/revision-0.7.2/CRANE_VERIFICATION.md).

## Телескопическая стрела и три жизни · 0.8.0

Форма крана и неподвижная задняя мачта сохранены. Две стороны стрелы имеют по три телескопические секции и покрывают свободный увод всех установленных этажей. Интерфейс сохранён на Fluid Functionalism/Euclid/цветах Ida, текст и логотип адаптированы к светлому окружению. Камера чуть выше для показа улиц; во время игры следует за верхним этажом. Полная башня показана в финале. Механики/коллайдеры/баланс не менялись. Транспорт и художественная доводка моделей в Blender отложены до следующего визуального этапа. High/medium добавляют N8AO, мягкий свет/блики и SMAA; high использует PCSS и три локальных тёплых источника. Только стартовая сцена high получает размытие периферии. ## Рывки крыши и этажей · 0.12.1

Движущийся этаж рисуется обычными мешами с общими геометриями и материалами; визуальная модель сохраняется между попытками, body/collider — между раскачиванием, падением и посадкой. Уложенная башня использует нативные постоянные instanced buffers, обновляемые только при посадке и включении окон финала. Все четыре типа этажей, крыша, объёмные цифры, шейдеры и код пожелания/конфетти подготавливаются в загрузке; догрузки на 7-м/17-м/20-м этажах удалены. Этаж и каретка используют одно время кадра. После появления пожелания камера плавно адаптируется к новому размеру canvas. Проверки — design/revision-0.12.1/VERIFICATION.md.


## Перевес башни · 0.14.0

Добавлена только механика потери опоры, вдохновлённая пользовательским примером https://levbakharev.art/panelka/. Код реализации свой. После каждой успешной посадки проверяется центр массы всех этажей выше каждого контакта (равная масса этажей). При выходе за реальную область пересечения опрокидывается часть выше самой нижней нарушенной опоры, вплоть до всей башни. Последний этаж также проверяется до запуска финала. Посадочные координаты и натуральное падение сохранены; выравнивания нет.

Падающая часть использует один Rapier body с коллайдерами этажей и те же InstancedMesh/окна/украшения. Пауза останавливает физику и новый раунд; обычное управление блокируется фазой collapse. Дизайн, ассеты, освещение, кран, скорость и пороги попаданий сохранены. Проверки: design/revision-0.14.0/VERIFICATION.md.

## Доступный баланс · 0.15.0

Каркас держит небольшой перевес за счёт резерва соединений .6m, а основание имеет массу четырёх этажей. Это игровой запас прочности, а не инженерный расчёт креплений. Неустойчивость показывает отношение нагрузки к пределу самого нагруженного соединения; тот же расчёт используется для падения. При 55% подсказка направляет следующий этаж в противоположную сторону, при 75% счётчик выделяется фирменным синим, 100% означает падение. Небольшие смещения не выравниваются автоматически. Скорость и размах подачи снижены; на последнем этаже окно попадания около 721ms. Проверки: design/revision-0.15.0/VERIFICATION.md.
